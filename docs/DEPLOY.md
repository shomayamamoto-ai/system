# 公開の手順書

予約システムを、インターネットから使える状態にするための手順です。
「サーバーを1台借りて、Docker で動かす」方法を説明します。

## 用意するもの

| 用意するもの | 説明 |
| --- | --- |
| サーバー | 月額数百円〜の VPS（仮想サーバー）で足ります。OS は Ubuntu などの Linux を選びます |
| ドメイン | `yoyaku.example.com` のような、予約ページのアドレスです |
| Docker | サーバーに入れておくソフトです。入れ方は Docker の公式サイトの案内に従ってください |
| メールサービス（任意） | お客様へメールを送る場合に必要です。SMTP の接続情報を控えておきます |

## 手順

### 1. ドメインをサーバーに向ける

ドメインの管理画面で、ドメインの「A レコード」にサーバーの IP アドレスを設定します。
反映には、数分〜数時間かかることがあります。

### 2. サーバーの 80 番と 443 番のポートを開ける

サーバー会社の管理画面（ファイアウォールの設定）で、80 番と 443 番を開けます。
HTTPS の証明書を自動で取得するために、両方が必要です。

### 3. プログラムをサーバーに置く

```bash
git clone https://github.com/shomayamamoto-ai/system.git
```

```bash
cd system
```

### 4. 設定ファイルを作る

```bash
cp .env.example .env
```

`.env` を開き、`DOMAIN` と `ADMIN_PASSWORD` を書き換えます。
メールを送る場合は、`SMTP_HOST` などもここに書きます。

### 5. 起動する

```bash
docker compose up -d --build
```

数十秒待ってから、ブラウザで `https://（設定したドメイン）/` を開きます。
管理画面は `https://（設定したドメイン）/admin` です。
ログインID `admin` と、`.env` に書いたパスワードでログインします。

### 6. 最初にやること

1. 「設定」で、ページの名前・担当者・受付時間・メニューを実際の内容に書き換える
2. 「設定」→「ログイン用アカウント」で、担当者ごとのアカウントを作る
3. メールを使う場合は、「設定」→「お客様へのメール」の「テスト送信」で届くか確認する
4. スマホから予約ページを開き、テストの予約を1件入れて、流れを確認する

## 日々の運用

| やりたいこと | コマンド |
| --- | --- |
| 動いているか確認する | `docker compose ps` |
| 記録（ログ）を見る | `docker compose logs --tail 100 app` |
| 止める | `docker compose down` |
| 新しい版に更新する | `git pull` のあとに `docker compose up -d --build` |

`https://（ドメイン）/healthz` を開いて `ok` と表示されれば、サーバーは動いています。
外部の監視サービスを使う場合は、このアドレスを登録してください。

## データの控え（バックアップ）

データは `yoyaku-data` という保存場所（Docker のボリューム）に入っています。
システムが1日1回、自動で控えを作ります（直近14日分）。

ただし、この控えは同じサーバーの中にあります。
サーバーごと壊れた場合に備えて、定期的に手元へコピーしてください。

```bash
docker compose cp app:/data ./backup-$(date +%F)
```

管理画面の「データ」→「CSVで書き出す」でも、予約の一覧を保存できます。

### 控えから戻す

```bash
docker compose down
```

```bash
docker compose run --rm app sh -c "cp /data/backups/db-2026-11-16.json /data/db.json"
```

```bash
docker compose up -d
```

`db-2026-11-16.json` の部分は、戻したい日付の控えの名前に置き換えます。

## うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| ページが開かない | ドメインがサーバーの IP を向いているか。80 番・443 番のポートが開いているか。`docker compose logs caddy` にエラーが出ていないか |
| 「保護されていない通信」と出る | 証明書の取得に失敗しています。上の2点を確認し、数分待ってから開き直してください |
| ログインできない | `.env` の `ADMIN_PASSWORD` を確認します。書き換えたら `docker compose up -d` で反映します。15分に8回まちがえると、一時的にログインできなくなります |
| メールが届かない | 管理画面の「テスト送信」でエラーの内容を確認します。迷惑メールフォルダも確認してください |
| 起動しない（データを読み込めません） | データファイルが壊れています。「控えから戻す」の手順で戻してください |

## 個人情報の取り扱いについて

このシステムは、お客様の氏名・メールアドレス・電話番号・相談内容を保存します。
公開する前に、次の点をご確認ください。

- 予約ページの案内文などで、個人情報の利用目的を伝える（プライバシーポリシーの用意）
- サーバーの管理画面や `.env` を見られる人を、必要な人だけに限る
- 不要になった控えのファイルは、手元に残したままにしない

法律上の義務の詳細は、事業の内容によって変わります。
必要に応じて、専門家へご確認ください。
