# 面談・相談予約システム

お客様がWebから面談を予約でき、担当者のスケジュールと自動で連動し、
予約やデータ読み込みを画面内に通知し、たまったデータから改善案を出すシステムです。
外部ライブラリは使っておらず、Node.js（18以上）だけで動きます。

## 使い方

```bash
npm start
```

- 予約ページ（お客様用）: http://localhost:3000/
- 管理画面（担当者用）: http://localhost:3000/admin

公開する前に、管理画面のパスワードを必ず設定してください。

```bash
ADMIN_PASSWORD=好きなパスワード npm start
```

| 環境変数 | 役割 | 初期値 |
| --- | --- | --- |
| `PORT` | 待ち受けるポート番号 | `3000` |
| `ADMIN_PASSWORD` | 管理画面のパスワード（未設定だと誰でも開けます） | なし |
| `DATA_FILE` | データの保存先 | `data/db.json` |
| `TRUST_PROXY` | nginx などの後ろで動かすときに `1` を指定（接続元の判定と、HTTPS専用クッキーに使います） | なし |

## できること

| 機能 | 内容 |
| --- | --- |
| 予約 | 月カレンダーで空き状況（○ 空きあり／△ 残りわずか／× 空きなし）を見ながら、メニュー・担当者（指名なしも可）・日時を選んで予約。確認用リンクからキャンセルも可能 |
| スケジュール連動 | 予約と、管理画面で入れた予定（会議・外出など）が入った時間は、予約ページの空き枠から自動で消える。二重予約は不可 |
| カレンダー | 週表示と月表示を切り替え。管理画面から予約の追加（電話・対面の受付用）、日時・担当者の変更、状態の変更ができる |
| 予約一覧 | 名前・メール・電話・相談内容での検索、状態と期間での絞り込み、CSV書き出し |
| 顧客 | メールアドレスごとに予約をまとめ、来談回数・キャンセル回数・来談履歴を表示 |
| 通知 | 新規予約・変更・キャンセル・データ読み込みの結果を、「通知」タブと画面右下に表示（15秒ごとに更新） |
| データ | 過去の予約データをCSVで読み込み・書き出し。動作確認用のサンプルデータも登録・削除できる |
| 分析・改善案 | 稼働率・キャンセル率などを前の期間と比較し、週（月）ごとの推移をグラフで表示。改善案は優先度順に並び、効果の試算が付く。判定の目安は画面から変更できる |
| 設定 | 担当者と受付時間、メニューと所要時間、予約枠の刻み、受付期間、当日の受付締切 |

## 安全のための仕組み

| 仕組み | 内容 |
| --- | --- |
| ログイン | パスワードでログインし、12時間で自動的に切れる。合言葉はブラウザの JavaScript から読めないクッキー（HttpOnly・SameSite=Strict）に保存 |
| 連続アクセスの制限 | 同じ接続元から、ログインは15分に8回、予約・キャンセルは10分に10回、API全体は1分に300回まで |
| 自動バックアップ | 1日1回、その日の最初の保存の前に `data/backups/` へ控えを保存（直近14日分）。データファイルが壊れている場合は、上書きせずに起動を止める |
| 不正な送信の防止 | 書き込みは JSON 形式だけ受け付け、ほかのサイトからの送信を防ぐ。画面の埋め込みや外部スクリプトの実行も禁止（CSP などのヘッダー） |
| CSVの安全対策 | 書き出すときに、表計算ソフトで数式として実行されうる文字（`=` `+` `-` `@`）の前に `'` を付ける |

バックアップから戻すときは、サーバーを止めてから、
`data/backups/db-日付.json` を `data/db.json` に上書きコピーしてください。

## CSVの形式

1行目は見出しです。「日付」「開始」は必須で、ほかは空欄でも読み込めます（文字コードは UTF-8）。

```csv
日付,開始,メニュー,担当者,氏名,メール,ステータス,受付日
2026-10-01,10:00,初回相談（30分）,担当者A,山田 太郎,taro@example.com,完了,2026-09-25
```

- ステータス: `予約済` / `完了` / `キャンセル` / `無断キャンセル`（空欄なら、過去は「完了」、未来は「予約済」）
- 登録されていない担当者・メニューの名前は、自動で追加します
- 同じ予約（日付・開始・担当者・氏名が同じ）は、重複としてスキップします

## 改善案の出し方

AIは使わず、目安の数値と実際の数字を比べて判定しています。
目安の初期値は仮に置いたもので、業界の公式な基準ではありません。
分析タブの「改善案を出す目安の数値を変更する」から、実際の運用に合わせて調整してください。

「試算」は、目安まで改善できたと仮定した場合の単純な計算です。実際の効果を保証するものではありません。

## 構成

```
server.js          サーバー本体（API と画面の配信）
lib/core.js        予約・空き枠計算・通知・CSV読み込み
lib/analytics.js   集計と改善案のルール
public/            予約ページと管理画面
test/              自動テスト（npm test）
```

## 知っておいてほしい制限

- データは1つのJSONファイルに保存します。1台のサーバーで動かす小〜中規模の利用を想定しています
- 時刻は日本時間（Asia/Tokyo）で扱います
- メールやLINEなど、外部への通知は行いません（画面内の通知のみ）
- Googleカレンダーなど、外部カレンダーとの連動はありません
- 管理画面のパスワードは1つを共有する方式です（担当者ごとのアカウントはありません）
- インターネットに公開する場合は、nginx などで HTTPS にしたうえで `TRUST_PROXY=1` を指定してください
- サーバーを再起動すると、ログインは切れます（もう一度ログインすれば使えます）
- 連続アクセスの制限は接続元（IPアドレス）ごとです。同じ回線を多人数で共有している場合は、まとめて数えられます
