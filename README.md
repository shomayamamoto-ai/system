# 面談・相談予約システム

お客様がWebから面談を予約でき、担当者のスケジュールと自動で連動し、
予約やデータ読み込みを通知し、たまったデータから改善案を出すシステムです。
Node.js（18以上）で動きます。

## 使い方

```bash
npm install
```

```bash
ADMIN_PASSWORD=好きなパスワード npm start
```

- 予約ページ（お客様用）: http://localhost:3000/
- 管理画面（担当者用）: http://localhost:3000/admin
  （最初は、ログインID `admin` と、上で決めたパスワードでログインします）

| 環境変数 | 役割 | 初期値 |
| --- | --- | --- |
| `PORT` | 待ち受けるポート番号 | `3000` |
| `ADMIN_PASSWORD` | ログインID `admin` のパスワード。未設定のままアカウントも作らないと、管理画面は誰でも開けます | なし |
| `DATA_FILE` | データの保存先 | `data/db.json` |
| `TRUST_PROXY` | nginx などの後ろで動かすときに `1` を指定（接続元の判定と、HTTPS専用クッキーに使います） | なし |
| `PUBLIC_URL` | 公開しているアドレス（例: `https://yoyaku.example.com`）。メールに予約確認ページのリンクを入れるために使います | なし |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` | メールを送る設定（下の「メールを送る設定」を参照） | なし |

## できること

| 機能 | 内容 |
| --- | --- |
| 予約 | 月カレンダーで空き状況（○ 空きあり／△ 残りわずか／× 空きなし）を見ながら、メニュー・担当者（指名なしも可）・日時を選んで予約 |
| お客様による確認・変更 | 確認用リンクから、予約内容の確認・日時の変更・キャンセルができる（締切を「面談の何時間前まで」と設定可能）。予約をスマホのカレンダーや Google カレンダーに追加できる |
| スケジュール連動 | 予約、個別の予定、毎週くり返す予定、休憩時間、休業日は、予約ページの空き枠から自動で外れる。二重予約は不可 |
| 受付時間 | 担当者ごと・曜日ごとに、受付時間と休憩（昼休みなど）を設定できる。祝日などの休業日も登録できる |
| カレンダー | 週表示と月表示を切り替え。管理画面から予約の追加（電話・対面の受付用）、日時・担当者の変更、状態の変更ができる |
| 予約一覧・顧客 | 名前などでの検索、状態と期間での絞り込み、CSV書き出し。お客様ごとの来談回数・履歴の表示 |
| 通知 | 新規予約・変更・キャンセル・データ読み込みの結果を、「通知」と画面の端に表示（15秒ごとに更新） |
| メール | 予約・変更・キャンセルのときと、面談の前日（リマインド）に、お客様へ自動でメールを送る |
| アカウントと操作履歴 | 担当者ごとにログインを分けられる。「だれが・いつ・何をしたか」を記録する（直近2000件） |
| 分析・改善案 | 稼働率・キャンセル率などを前の期間と比較し、推移をグラフで表示。改善案は優先度順に並び、効果の試算が付く。判定の目安は画面から変更できる |
| スマホ対応 | 予約ページ・管理画面とも、スマホの画面幅に合わせて表示が切り替わる（管理画面はメニューが画面下に移動） |

## アカウントと権限

「設定」→「ログイン用アカウント」で、担当者ごとのアカウントを作れます。

| 権限 | できること |
| --- | --- |
| 管理者 | すべての操作 |
| 担当者 | カレンダー・予約・顧客・通知・分析の閲覧と、予約・予定の操作。設定の変更、データの読み込み、アカウントの管理、操作履歴の閲覧はできない |

パスワードは、元に戻せない形（scrypt）に変換して保存します。
パスワードを忘れたときは、管理者が「パスワード変更」から新しいものを設定してください。

## メールを送る設定

メールは、お使いのメールサービスの「SMTP」という送信の窓口を通して送ります。
下の値は、メールサービスの管理画面や案内ページで確認してください。

```bash
SMTP_HOST=smtp.example.com SMTP_PORT=587 SMTP_USER=ユーザー名 SMTP_PASS=パスワード MAIL_FROM=yoyaku@example.com PUBLIC_URL=https://yoyaku.example.com ADMIN_PASSWORD=好きなパスワード npm start
```

- `SMTP_PORT` が `465` のときは最初から暗号化して接続し、それ以外（`587` など）は接続後に暗号化します
- 設定できたら、「設定」→「お客様へのメール」の「テスト送信」で届くか確認してください
- メールが送られるのは、予約ページと管理画面から登録した予約だけです。CSVで読み込んだ予約とサンプルには送りません
- 送信に失敗しても予約は成立し、管理画面の通知に「メールを送れませんでした」と表示されます
- 前日リマインドは10分ごとに確認して送ります。サーバーが止まっている間は送られません

## 安全のための仕組み

| 仕組み | 内容 |
| --- | --- |
| ログイン | 12時間で自動的に切れる。合言葉はブラウザの JavaScript から読めないクッキー（HttpOnly・SameSite=Strict）に保存 |
| 連続アクセスの制限 | 同じ接続元から、ログインは15分に8回、予約・変更・キャンセルは10分に10回、API全体は1分に300回まで |
| 自動バックアップ | 1日1回、その日の最初の保存の前に `data/backups/` へ控えを保存（直近14日分）。データファイルが壊れている場合は、上書きせずに起動を止める |
| 不正な送信の防止 | 書き込みは JSON 形式だけ受け付け、ほかのサイトからの送信を防ぐ。画面の埋め込みや外部スクリプトの実行も禁止（CSP などのヘッダー） |
| CSVの安全対策 | 書き出すときに、表計算ソフトで数式として実行されうる文字（`=` `+` `-` `@`）の前に `'` を付ける |

バックアップから戻すときは、サーバーを止めてから、
`data/backups/db-日付.json` を `data/db.json` に上書きコピーしてください。

## CSVの形式

1行目は見出しです。「日付」「開始」は必須で、ほかは空欄でも読み込めます（文字コードは UTF-8）。

```csv
日付,開始,メニュー,担当者,氏名,メール,ステータス,受付日
2026-10-01,10:00,初回相談（30分）,担当者A,山田 太郎,taro@example.com,完了,2026-09-25
```

- ステータス: `予約済` / `完了` / `キャンセル` / `無断キャンセル`（空欄なら、過去は「完了」、未来は「予約済」）
- 登録されていない担当者・メニューの名前は、自動で追加します
- 同じ予約（日付・開始・担当者・氏名が同じ）は、重複としてスキップします

## 改善案の出し方

AIは使わず、目安の数値と実際の数字を比べて判定しています。
目安の初期値は仮に置いたもので、業界の公式な基準ではありません。
分析タブの「改善案を出す目安の数値を変更する」から、実際の運用に合わせて調整してください。

「試算」は、目安まで改善できたと仮定した場合の単純な計算です。実際の効果を保証するものではありません。

## 構成

```
server.js          サーバー本体（API と画面の配信、ログイン、メール送信の呼び出し）
lib/core.js        予約・空き枠計算・通知・CSV読み込み
lib/analytics.js   集計と改善案のルール
lib/auth.js        アカウントと操作履歴
lib/mailer.js      メールの文面と送信、前日リマインドの判定
public/            予約ページと管理画面
test/              自動テスト（npm test）
```

## 知っておいてほしい制限

- データは1つのJSONファイルに保存します。1台のサーバーで動かす小〜中規模の利用を想定しています
- 時刻は日本時間（Asia/Tokyo）で扱います
- 祝日は自動では入りません。休業にする日は「設定」→「休業日」で登録してください
- 休憩は、1日につき1つまで設定できます
- LINE など、メール以外の外部への通知は行いません
- Googleカレンダーなどとの自動同期はありません（お客様が自分のカレンダーに予約を追加するボタンはあります）
- インターネットに公開する場合は、nginx などで HTTPS にしたうえで `TRUST_PROXY=1` を指定してください
- サーバーを再起動すると、ログインは切れます（もう一度ログインすれば使えます）
- 連続アクセスの制限は接続元（IPアドレス）ごとです。同じ回線を多人数で共有している場合は、まとめて数えられます
- 外部ライブラリは、メール送信用の nodemailer の1つだけです
